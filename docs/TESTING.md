# Windows 人工故障验收

本轮 3～30 秒周期、目标选择、持久化和工作模式的专门 checklist 见 [ROUND2.md](ROUND2.md)。以下环境矩阵继续适用；正常状态门槛随目标数为 1/1、2/2、2/3。

自动化不切断用户网络。以下操作由你在不影响重要任务的时间手动执行，先启动 `--dashboard`、开启通知，并保留日志。每项结束后恢复原网络配置。先用 Test Notification 确认 Windows 能显示通知。

| 场景 | 方法 | 预期 |
|---|---|---|
| 正常 VPN | 开启系统代理/TUN，持续至少 3 轮 | 当前启用目标达到门槛，HEALTHY 或持续高延迟状态 |
| 关闭 VPN | 关闭客户端连接，保持本机网络 | 全部真正连接失败持续 3 轮才 Down；如本机仍能直连，不应假报 |
| VPN 重连 | 恢复连接 | 连续 2 轮 quorum 成功后仅一次 Recovery，记录事件时长 |
| 拔网线 / 关闭 Wi-Fi | 手动关闭当前物理连接 | 无 operational 网卡则 NO_INTERNET；虚拟网卡在线可能 VPN_DOWN |
| DNS 异常 | 在隔离测试机上配置无效 DNS | DNS_ERROR；有代理远端解析/缓存时不保证本地 DNS 错误可见 |
| 部分网站失效 | 用测试机防火墙阻断一个目标 | 不应报 VPN_DOWN，显示部分失败/质量异常 |
| 服务 403/429/5xx | 自动化本机服务器已覆盖 403/429；实际服务限制观察日志 | reachable=True，服务错误不等同 VPN 掉线 |
| 延迟升高 | 调低 high_ms 验证，再恢复；或测试机做延迟注入 | 连续异常后黄色，冷却期内不反复通知 |
| 切换 VPN 节点 | 客户端切节点 | 短暂波动不必报警；持续异常按轮确认，恢复去重 |
| 关闭本地代理端口 | 停止提供系统代理的客户端 | PROXY_CONNECTION_REFUSED 等，持续失败后 Down |
| HTTP 超时 | 自动化两个目标延迟 2 秒、期限 1 秒 | 两请求并行超时，总耗时约 1 秒，界面可用 |
| 证书错误 | 隔离测试服务使用不可信证书 | SSL_ERROR，绝不忽略证书继续判成功 |
| PAC 卡住/探测进程崩溃 | 进程 smoke 强制杀子进程/触发看门狗 | UNKNOWN + 诊断，自动重启，不伪装网络故障 |
| 睡眠后唤醒 | 启动监测，睡眠后唤醒 | 不累计未检测轮次，不集中补发旧计时器请求 |
| Windows 网络切换 | 切 Wi-Fi/Ethernet | 下一轮新管理器/连接重新探测，短暂波动防抖 |
| 暂停/恢复 | 托盘暂停后等待，再恢复 | 暂停无请求，恢复清空未确认计数 |
| 正在超时时退出 | 故障期间选择 Exit | 主进程在约 2 秒有界等待后结束，无遗留探测子进程 |
| 多实例 | 同一数据目录启动第二实例 | 提示已有实例，不开启第二份后台监测 |
| Windows 通知 | 托盘 Test Notification；再执行实际掉线/恢复 | 真实系统通知显示；勿扰模式按系统设置处理 |
| 数小时后台 | 普通使用至少 8 小时，随后 24–72 小时 | 无崩溃、无通知风暴，CPU/内存不持续增长，日志轮转 |
| Windows 10 / 干净 Windows 11 | 无 Python 的测试机复制 EXE | GUI、探测子进程、TLS、通知均正常 |

性能记录要合计主程序、onefile 引导进程和探测子进程；每 10–30 分钟记工作集和累计 CPU，日志按当前文件 + 5 备份检查。睡眠前已确认故障的时长含未观察间隙，应作为估算解释。未完成这份人工矩阵前，不能宣称长期稳定性或全部客户端兼容已经通过。
